# 主动词库

把「认识但不会用」的英文词，练成会在作文里主动用出来的词。

背单词和写作用词是断开的：阅读时认得的词，落到笔上就是想不起来，想起来了搭配也常常错。主动词库不加新的背诵环节，而是把你已经在背的词直接塞进一段限定写作任务里——勾词、按这批词出题、读 AI 示范或自己写、AI 逐词判定用没用出来、搭配地不地道，用出来且地道才算真正掌握。

在线地址：<https://active-vocab-em96hhnq10h.qoder.zone>（Qoder Sites 部署，当前访问策略为指定账号，需登录后打开）

## 核心闭环

1. **收词**：在词本的粘贴框把自己正在背的笔记整段粘进来，`/intake` 整理成词卡，新词同时补进写作页的本次目标词（目标词已选满时只入库，并说明哪几个没勾上）；也可以「手动填一个」。词库不预设任何词，首屏是空的，空着时有「试试粘这段」用样例走一遍闭环。
2. **出题**：在写作页左栏「本次目标词」点 2~5 个词，题干按这批词的主题生成，不是固定模板轮播——勾海洋主题的词，出的就是海洋的题。
3. **练用**：两条路共用同一篇幅要求。**A 读 AI 示范短文**（按题干和篇幅现写，整段连着读、再逐句拆结构与生词，点任意单词看释义）；**B 我自己写**（写完 AI 逐词判定是否用出、搭配是否自然，给得分和可抄的改法）。两条路的结果都能「保存这篇」，存进「习作集」那一屏。
4. **进阶**：掌握度从 `认识` 推到 `练用中`，再到 `会用`。

## 掌握度

| 状态     | 中文   | 怎么到                                             |
| -------- | ------ | -------------------------------------------------- |
| `passive`  | 认识   | 粘贴导入或手动收词的初始状态                       |
| `training` | 练用中 | 读完 AI 示范短文（路径 A 的上限），或在词卡一键标记 |
| `active`   | 会用   | 自己写（路径 B），AI 判为用出且搭配地道            |

只升不降：读示范最多到 `training`，亲手写出来且用对搭配才计入 `active`。判定与回写在 `src/features/writing/masteryUpdate.ts`，类型契约在 `src/types.ts`。

## 界面

顶部三个视图切换（地址分别是 `#/write`、`#/words` 与 `#/saved`，后退键能退回上一屏），进哪个视图就重算哪个视图的数据。

- **写作**：左「本次目标词」（点词卡勾选，卡面带释义与掌握度色点；空词库时给「去词本收词」入口）、右「限定写作」（篇幅、A/B 两条路、题干与目标词、结果区）。
- **词本**：一行工具条（粘贴收词 / 手动填一个）+ 词卡列表按掌握度筛选。粘贴框默认收起，点「粘贴收词」摊开；词本还空着时直接摊开，配「试试粘这段」样例走一遍闭环。收词结果只占工具条里的一行（`已加入 7 个词，autonomous、step up 没勾上（目标词已满）。去写作`），不再单独占一块把词表推走。词卡显示词头、词性、释义与搭配，例句在点进去的学习视图里补。
- **篇幅四档**：自动（句数 = 目标词数，夹在 2~8 句，最多多一句，每句按 12~16 词估）/ 短 2~3 句 / 中 4~6 句 / 长 7~10 句，见 `src/features/writing/passageLength.ts`。示范短文与自写共用同一区间，写作时实时显示句数/词数偏短、达标还是偏长。换档位只改下一次生成的参数，已经生成的示范和点评不会被清掉；档位与这篇不一致时按生成当时那档判篇幅，并提示「这篇按 X 句写的，当前篇幅已改成 Y」，再点 A 才会按新档位重写。
- **示范读法**：新生成的示范默认落在「整段」——英文和全文译文在同一块里，中间一条细线，译文由逐句译文按序拼成，没讲齐就直说还差几句，不拼半截糊弄人。切到「逐句讲解」给译文、结构说明和按成分切分的原句高亮，某一句讲解失败可以单独重试。
- **习作集**：结果卡头顶的工具条上有「保存这篇」——A 在「整段 / 逐句讲解」旁边，B 在得分那一行右边，和读法按钮等高。存进这台设备的浏览器（最多 50 篇），刷新、换目标词、换篇幅重写都不会没；存过之后那个位置换成「已存进习作集」加一个「去习作集」。存示范时把当时已经生成的逐句讲解一起存成快照（译文、结构、成分、生词表，句数与条数都有上限），习作集点开就是离线可读的完整讲解，复制出去也带上这段。当时没讲过的示范，那一行给一个「补分析」——只在缺快照时出现，点了现调网关，成功就回写并自动摊开，失败只留一行原因、「补分析」还在（本地兜底那份没有译文，不算讲过，也不写进快照）。习作集是独立一屏（`#/saved`，顶栏按钮上直接写共存了几篇），每行给来源、自动取的名字（正文开头前 7 个词，截断处补省略号；名字不另存，跟着正文走，早期存下的那几篇也就一并有了标题）、篇幅、存的时间和「已带讲解」，标题下面一行直接列出当时勾选的目标词（词头 + 截到 18 字的释义，早期没记目标词的退到逐词判定里的词头），可展开看正文（示范连拼好的译文与讲解，习作连得分、总评与逐词判定）、复制或删除（删除要点两次确认，复制出去的第一行就是这个自动名字）。空屏时说明怎么存进来并给「去写作」。换浏览器看不到，也不上传。
- **点词查释义**：示范与讲解里的每个单词都是按钮，点开看它在这一句里的释义；词库里没有的词可以直接「收进词库」。
- **模型密钥**（页脚）：留空走访客看不见的站点 Secret；粘自己的 key 后所有生成请求改走自己的额度。输入框是密码型、保存即清空，界面只留尾号，值只在 `localStorage` 和请求头里。

词库与任务存在这台设备的浏览器 localStorage（键名 `tianchi.words` / `tianchi.tasks`），保存下来的习作集连同讲解快照存在同设备的 `tianchi.saved`（讲解按 12 句、每句 8 段成分、60 条生词封顶，免得 50 篇写不下），自带的模型密钥存在 `tianchi.modelkey`；写作框里的草稿只在当前页面内，刷新会没。除生成请求外不上传任何文本内容，题干与勾选项只在调用 AI 网关时发出去。

## AI 网关

前端只调同源 `/functions/v1/app/{intake,model-text,explain,gloss,feedback}`。站点密钥不下发浏览器；访客自带的那个 key 存在他自己的浏览器里，随请求头 `x-model-key` 交给网关用一次。

| 路由         | 作用                              | 入参                              | 出参                  |
| ------------ | --------------------------------- | --------------------------------- | --------------------- |
| `intake`     | 把任意粘贴文本整理成词卡          | `{ raw }`（≤6000 字）             | `{ ok, words[], model }`（≤30 条） |
| `model-text` | 按题干与篇幅生成示范短文          | `{ prompt, words[], length }`     | `{ ok, modelText, model }`   |
| `explain`    | 示范短文逐句讲解（译文/结构/成分）| `{ text, words[] }`               | `{ ok, explanation, model }` |
| `gloss`      | 单个词在该句语境下的释义          | `{ term, sentence }`              | `{ ok, entry, model }`       |
| `feedback`   | 逐词判定是否用出、是否地道        | `{ taskId, text, words[] }`       | `{ ok, feedback, model }`    |

`intake` 是收词的正门：不规定粘贴格式，一串单词、一段带释义的笔记都能进。返回的每条是 `{ headword, pos, meaningZh, theme, examples[≤2], collocations[≤4]{phrase,gloss} }`，字段缺了就是空串/空数组，词头已去重。词头有校验（`HEADWORD_OK`：英文开头、≤40 字符，模型把整行笔记、例句或中文释义当词头时直接丢掉），所以入库的一定是词而不是句子。`theme` 是模型对这批词共同话题的判断（如「海洋与环境」），入库后存成词卡的 `source: 粘贴导入 · ${theme}`，出题时按「·」后的主题生成题干——这就是「按词出题」的来源。

网关侧的约束（`functions/handler.ts`）：只接受 POST，请求体 ≤12000 字；`feedback` / `model-text` 的 `words[]` 为 1~8 条，`id` 与 `headword` 必填，`meaningZh` **允许空串**（刚粘贴导入的词可能还没有释义，缺释义不该让整次点评失败）；`explain` 词表缺失也能讲——习作集的「补分析」就靠这条：那一屏没有任务，只有当时存下的正文与目标词（词头 + 释义，搭配留空）。篇幅契约 `length = { minSentences, maxSentences, minWords, maxWords }`，网关把句数夹在 1~12、词数夹在 10~400 并保证 min ≤ max；请求没带 `length` 时按「自动」档同一条规则估（句数 = 词数、最多多一句、每句 12~16 词），免得前端改了档位网关还按老的写。

单次调用的成本天花板：输出 `max_tokens` 默认 4096（`gloss` 512、`explain` 4000），超时 20s（`explain` 45s），生成类请求在前端一次只排一路。没做按人头的赠送额度——那要在服务端记住谁用了几次，而站点没有数据库；账户侧的上限只能在模型服务商后台设。

密钥优先级：带 `x-model-key` 就用它（形状不对直接 `model_key_invalid`，一次上游都不打），没带才用站点 Secret，两个都没有才 `service_not_configured`。带了自带 key 时失败**不回落到站点 key**——那会悄悄花掉站主的额度，用户还以为走的是自己的。

上游走 DeepSeek 的 OpenAI 兼容接口（`https://api.deepseek.com/v1`），环境变量：`API_KEY`（Secret，填 DeepSeek 的 key，给没自带密钥的访客兜底）、`AI_MODEL`（默认 `deepseek-chat`）、`AI_BASE_URL`（可选，换服务商时用）。密钥只在 edge 运行时读取，打包产物里没有。

五路响应都带一个 `model` 字段，说明这次实际调的是哪个型号：上游自己报了具体版本（如 `deepseek-chat-v3`）就按它，没报才回落到 `AI_MODEL` 或默认值。前端把它显示在结果下面的「来源：AI 网关 · deepseek-chat」，没走成 AI 时不显示型号，只显示兜底原因——界面不猜型号。

**任何一路不通都不假装成功。** 缺 key 返回 `service_not_configured`，上游失败返回 `upstream_unavailable`，自带密钥形状不对或被上游拒绝返回 `model_key_invalid` / `model_key_rejected`，前端每一路都有本地兜底并在结果里写明这次为什么没走 AI：点评退回本地 mock 规则、示范退回词卡例句拼接、讲解只切句不给译文、收词按换行与逗号切分只填 `headword`。返回体也不带上游细节（状态码、异常文本、密钥）。

生成类请求（`intake` / `model-text` / `explain` / `feedback`）一次只跑一路：写作屏和词本屏各转各的圈，但请求在 `aiClient.ts` 里排队，谁先点谁先走，不会两路同时打到上游。`gloss` 是短请求，走旁路不排队，点词查释义不会被前面正在生成的长文卡住。

## 技术选型

- **Vite 7 + TypeScript 5.6**，无前端框架：视图是模板字符串 + `escapeHtml` 转义，状态在模块闭包里，改动走重绘；没有虚拟 DOM 与运行时依赖，构建产物就是静态资源。
- **样式**：`src/style.css` 一套设计令牌（配色/字体/圆角/按钮），`public/assets/ui/cards.css`、`public/assets/motion/motion.css` 是卡片与动效的公共层，字体子集本地化在 `public/assets/fonts/`。
- **AI 网关**：Deno Function（`functions/index.ts` 入口 + `functions/handler.ts` 全部逻辑），单文件、无框架，按路径尾段路由。
- **存储**：浏览器 localStorage，无账号、无服务端数据库。每个浏览器只看得见自己的词库与密钥。

```
src/

public/assets/             # 字体、卡片与动效样式、分享图
dev/                       # 网关断言与本地假上游
docs/                      # 任务清单与过程截图
```


## 部署

站点部署在 Qoder Sites（项目 slug `active-vocab`），`dist/` 为静态产物，`functions/` 为同源 AI 网关，密钥放在站点 Settings 的 Secret `API_KEY` 里。这个 Secret 是兜底：访客在页脚粘了自己的模型密钥时，那次请求用他自己的 key，不消耗站点的额度。
